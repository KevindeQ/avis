# 99 — Decisions, Assumptions & Open Questions

This document tracks where each design decision came from:
- **R**: required by [`idea.md`](../idea.md)
- **D**: decided by the project owner during design clarification
- **A**: an assumption (best guess) made while writing these documents. Each one can be overridden. Changing one means updating the referenced documents.

## 4. Notes on `idea.md`
- Line 2 still lists "evaluated" in the long-term aim. That's consistent with "evaluation is postponed", so no change is needed.
- The idea document no longer mentions rendered sensors, but the render graph still keeps multi-view support (for picture-in-picture and sensor-aligned views). That keeps a future synthetic-sensor iteration cheap.
- The existing code diverges from the target in a few places the documents call out: `io_executor` owns its own threads instead of running on the default pool ([07 §2](07-io-layer.md#2-components)), `transform::to_matrix` composition order ([08 §4.1](08-scene-management.md#41-transform-propagation)), `serializer.h` moves to `avis::network` ([02 §4](02-communication.md#4-message-framing)), and the custom task system in `avis::threading` (`task_system`, `task_scheduler.h`, `work_stealing_deque.h`, `task_inbox.h`, `task.h`) is replaced by the parallel scheduler backend ([15](15-parallel-scheduler.md), D-60). The RHI no longer diverges (task 6, 2026-10-29): the old `render_hardware_interface` that exposed D3D12 types is replaced by the design of [09](09-rhi.md), and the remaining differences are recorded in 09 itself. The render pass prototype (`include/avis/graphics/`, `lib/avis/graphics/`) and the Visualizer's `scene_renderer` still use the old API and are out of the build until the render graph task ([10](10-render-graph.md)).

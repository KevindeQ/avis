# 99 — Decisions, Assumptions & Open Questions

This document tracks where each design decision came from:
- **R**: required by [`idea.md`](../idea.md)
- **D**: decided by the project owner during design clarification
- **A**: an assumption (best guess) made while writing these documents. Each one can be overridden. Changing one means updating the referenced documents.

| D-41 | **The renderer owns all GPU copies** of meshes, materials and textures. | D-42 | **Presentation-only republish.** UI commands that only change what's shown (selection, visibility, helpers, representation settings, `visualization` edits, *Reset*) are applied by the simulation thread in every clock state, which then republishes the snapshot with unchanged step fields, coalesced to at most one republish per 16 ms. | D-43 | **Interop without cross-device GPU waits.** Avis takes any free slot, checked on the CPU through `when_reached(consumed, picked[i])`. ## 4. Notes on `idea.md`
- Line 2 still lists "evaluated" in the long-term aim. That's consistent with "evaluation is postponed", so no change is needed.
- The idea document no longer mentions rendered sensors, but the render graph still keeps multi-view support (for picture-in-picture and sensor-aligned views). That keeps a future synthetic-sensor iteration cheap.
- The existing code diverges from the target in a few places the documents call out: `render_hardware_interface` exposes D3D12 types ([09 §2](09-rhi.md#2-module-layout)), `io_executor` owns its own threads instead of running on the default pool ([07 §2](07-io-layer.md#2-components)), `transform::to_matrix` composition order ([08 §4.1](08-scene-management.md#41-transform-propagation)), `serializer.h` moves to `avis::network` ([02 §4](02-communication.md#4-message-framing)), and the custom task system in `avis::threading` (`task_system`, `task_scheduler.h`, `work_stealing_deque.h`, `task_inbox.h`, `task.h`) is replaced by the parallel scheduler backend ([15](15-parallel-scheduler.md), D-60).
